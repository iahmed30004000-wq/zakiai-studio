# نشر النظام وصناديق النماذج على السيرفر — خطوة بخطوة

> **تنبيه مهم:** الصندوق العام وصندوقا LTX وWan القديمين **انكتبوا ما انجرّبوا على كرت شاشة حقيقي**. الاختبارات اللي ركضت كانت بنموذج «وهمي» وبمكتبة diffusers مزيّفة، وبتثبت إن السلسلة كلها شغّالة (الطابور، القفل، الإلغاء، الرسائل، اكتشاف الأوزان، بناء النداء لكل عيلة نموذج، الربط بمكتبة النماذج وبالتحريك). تواقيع نماذج diffusers اتفحصت على نسخة 0.36 بشكل ثابت، بس **تحميل الأوزان وتشغيلها على الكرت لسا ما انفحص**. أول تشغيل حقيقي على السيرفر لازم يكون وإنت قاعد، وإذا طلع خطأ غريب ابعتلي نص الخطأ من `docker compose logs`.

## شو هو «الصندوق»؟

**الصندوق العام (`engine`)** حاوية Docker واحدة، متل «غرفة مقفولة» فيها كل مكتباتها، بتقرا **أي أوزان بصيغة diffusers** بتحطها بمجلد الأوزان: توليد صور، تعديل صور (بحتى 3 صور مرجعية)، تكبير صور، تحريك (Wan، LTX…)، وموسيقى ومؤثرات (Stable Audio). أنت بتنزّل الأوزان مرة وحدة، ومن «مكتبة النماذج» بالواجهة بتختار شو يشتغل.
**مثال:** نزّلت أوزان Qwen-Image على السيرفر ← الصندوق بيلاقيها لحاله وبيطلّعها بالقائمة مع حجمها ورخصتها ← بتكبس «اختار» وبتجرّب ← صور المشاهد بتطلع منها.

**قفل الكرت:** الكرت بيشتغل عليه شغلة وحدة بكل لحظة. لو الصندوق عم يولّد صورة وانطلب تحريك، التاني بيستنى دوره وما بينهار. ولما يجي دور نموذج تاني، الصندوق بيفرّغ الأول من ذاكرة الكرت. **والقفل مشترك مع الاستوديو نفسه** (حجم `vidpattern_gpu_locks`)، فلما أي برنامج نموذج بيستعمل الكرت، الواجهة بتقلّك «الكرت مشغول».

**الصندوقين القدام (LTX وWan):** كل واحد بنموذج ثابت. لسا موجودين بس بيشتغلوا بس مع `--profile legacy`. الصندوق العام بيغنيك عنهم: نفس الأوزان (مجلدي `LTX-Video` و`Wan2.2-TI2V-5B-Diffusers`) بيشغّلهم هو.

## 1. اللي بدك إياه

- سيرفر لينكس (Ubuntu 22.04 أو أحدث) فيه كرت NVIDIA، وتعريف الكرت (driver) مركّب.
- تتأكد إن الكرت شغّال: اكتب `nvidia-smi` — لازم يطلعلك جدول فيه اسم الكرت وذاكرته.
- مساحة فاضية: حسب النماذج اللي بتنزّلها (شوف الجدول بقسم 4: من 64 ميغا للتكبير لحد 54 جيجا لنموذج صور واحد) + 20 GB للصور.

## 2. تركيب Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER        # بعدها اطلع وادخل من جديد عشان تشتغل بدون sudo
docker --version                     # لازم يطلع رقم نسخة
```

## 3. تركيب nvidia-container-toolkit (عشان Docker يشوف الكرت)

هالأوامر من توثيق NVIDIA الرسمي — لو الروابط تغيّرت شوف توثيقهم (search: NVIDIA Container Toolkit install).

```bash
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

**اختبار:** لازم يطلعلك نفس جدول `nvidia-smi` من جوّا حاوية:

```bash
docker run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu22.04 nvidia-smi
```

## 4. وضع الأوزان (النماذج)

الأوزان ملفات ضخمة بتنزّلها **مرة وحدة** وبتحطها بمجلد واحد (`models/engines` افتراضياً، أو المكان اللي بتحدّده بـ `ENGINE_WEIGHTS_DIR` بملف `.env`). **كل نموذج بمجلد لحاله** فيه ملف `model_index.json` ومجلدات متل `transformer` و`vae`. الصندوق بيقراها «للقراءة فقط» وما بينزّل شي من الإنترنت وقت التشغيل.

**أوزان آمنة بس:** الصندوق بيرفض أي مجلد فيه ملف `.bin` أو `.pt` أو `.ckpt` أو `.pkl` أو `.py` (هالصيغ ممكن تشغّل كود لما تنفتح)، وأي مكوّن مش من مكتبتي diffusers وtransformers. الرفض بيظهر بالقائمة بسببه بالعربي.

| النموذج | شو بيعمل | حجم التنزيل (تقريباً) | الرخصة | المجلد |
|---|---|---|---|---|
| Qwen-Image | صور من وصف طويل | 54 GB | Apache-2.0 ✓ | `models/engines/Qwen-Image` |
| Qwen-Image-Edit-2509 | تعديل صور (لحد 3 صور مع بعض) | 54 GB | Apache-2.0 ✓ | `models/engines/Qwen-Image-Edit-2509` |
| FLUX.1-schnell | صور سريعة (4 خطوات) | 31 GB (بعد استثناء الملف الأحادي) | Apache-2.0 ✓ | `models/engines/FLUX.1-schnell` |
| Real-ESRGAN x4plus | تكبير صور ×2 ×3 ×4 | 64 MB | BSD-3 ✓ | `models/engines/upscale/RealESRGAN_x4plus.pth` |
| Wan2.2 TI2V 5B | تحريك صورة أو نص لفيديو | 32 GB | Apache-2.0 ✓ | `models/engines/Wan2.2-TI2V-5B-Diffusers` |
| LTX-Video | تحريك سريع | 27 GB (بعد الاستثناء، وإلا 236 GB!) | «other» — **مشروطة بإيراد شركتك، راجعها** | `models/engines/LTX-Video` |

**ملاحظات على التنزيل:**
- FLUX.1-schnell لما جرّبنا نوصله بلا حساب رجع «401 غير مصرّح» — يعني غالباً المستودع بيطلب تسجيل دخول Hugging Face وموافقتك على شروطه. سجّل دخول بـ `huggingface-cli login` قبل التنزيل.
- الاستثناء بـ FLUX بيوفّر 22 GB: المستودع فيه نسخة أحادية الملف مكرّرة، والصندوق ما بيحتاجها.
- LTX: **لازم** `--include` (مكتوب فوق)، لأنو المستودع فيه عشرات النسخ الكبيرة (13B) بحوالي 236 GB كلها. المطلوب بس مجلدات المكوّنات.
- **تحريك الصورة (i2v) مش لكل نماذج Wan:** الصندوق بيعرضه بس لنموذج «TI2V» (متل Wan2.2-TI2V-5B)؛ نماذج «نص لفيديو» (T2V) بتطلع بالقائمة بملاحظة «نص لفيديو بس». ومجلد نموذج فيه مجلد برابط رمزي (symlink) بيترفض — انسخ الملفات فعلياً.
- Stable Audio: المستودع محمي (متل FLUX) — سجّل دخول ووافق على الشروط أول. و**لازم** `--exclude "*.ckpt"`: المستودع فيه نسختين بصيغة `.ckpt` والصندوق بيرفض هالصيغة (ممكن تشغّل كود)، والنسخة الأحادية `model.safetensors` مكرّرة (4.8 GB زيادة). النموذج بيطلع بمكتبة النماذج لمهمتي «الموسيقى» و«المؤثرات» (نفس النموذج للتنتين)، وأقصى مدة 47 ثانية (`AUDIO_MAX_SECONDS`). الوصف بالإنجليزي.
- **كيف تتأكد إن المجلد صح:** جوّا كل مجلد لازم تلاقي `model_index.json` ومجلدات `transformer` و`vae`. بعد التشغيل (قسم 7) القائمة بتبيّنلك كل نموذج: ✓ جاهز أو مرفوض وليش.
- الأوزان الجديدة بتظهر لحالها بالقائمة بدون إعادة تشغيل (زر «حدّث القائمة»).

## 5. الإعدادات (ملف .env)

```bash
cp .env.example .env
openssl rand -hex 32          # بيطلّع كلمة عشوائية طويلة، انسخها
nano .env                     # حطها بعد ENGINE_TOKEN= واحفظ
chmod 600 .env                # بس إنت بتقرا الملف
```

**التوكن** هو «كلمة السر» بين النظام والصناديق. بدونها أي حدا على السيرفر ما بيقدر يطلب منها شي. **لا ترسله لأي حدا ولا تكتبه بمحادثة.** على السيرفر النظام بياخده من `.env` لحاله (الـ compose بيمرّره)، فبالواجهة ما بتحتاج تكتبه.

**إعدادات اختيارية بنفس الملف:** `ENGINE_OFFLOAD` (توفير ذاكرة الكرت)، `MAX_PIXELS` (سقف دقة الفيديو)، `MAX_SECONDS` (أطول لقطة فيديو)، و`AUDIO_MAX_SECONDS` (أطول مقطع صوت، الافتراضي 47)، و`UPSCALE_MAX_PIXELS` (سقف مساحة الصورة المكبّرة، الافتراضي 64 ميغابكسل).

**خزنة المفاتيح (على السيرفر):** مفاتيح الاتصالات وتوكنات «مكتبة النماذج» بتنحفظ مشفّرة بملف `secrets/vault.enc` (بدل مخزن ويندوز اللي مش موجود على لينكس). لازم عبارة سر للتشفير بملف `.env`:

```bash
openssl rand -base64 24       # انسخ الناتج
nano .env                     # حطه بعد VP_SECRETS_KEY= (16 حرف على الأقل)
mkdir -p secrets && chmod 700 secrets      # مجلد الخزنة (برّا library فما بيدخل النسخ الاحتياطي ولا جيت)
```

بدون `VP_SECRETS_KEY` الاستوديو بيرفض يحفظ أي مفتاح (ما بنكتب مفاتيح بملف نصي أبداً). **لو ضاعت العبارة أو اتغيّرت** المفاتيح المحفوظة بالخزنة ما بتنفتح (بتعيد إدخالها). الملف نفسه مشفّر، فلو انسرق لوحده ما بيفيد.

## 6. التشغيل

```bash
docker network create vidpattern_net                          # مرة وحدة بس: الشبكة اللي بتجمع النظام والصناديق
docker volume create vidpattern_gpu_locks                     # مرة وحدة بس: قفل الكرت المشترك بين الصناديق والنظام
docker compose -f docker-compose.engines.yml up -d --build    # بيشغّل الصندوق العام (engine). أول مرة بتاخد وقت (بيبني الصورة)
docker compose up -d --build                                  # النظام نفسه
```

الصندوقين القدام (اختياري، لو لسا بدك إياهم): `docker compose -f docker-compose.engines.yml --profile legacy up -d --build`.

**الواجهة:** `http://127.0.0.1:8000` على السيرفر. للدخول من جهازك استعمل نفق SSH: `ssh -L 8000:127.0.0.1:8000 user@server` وافتح `http://127.0.0.1:8000` عندك. (المنافذ كلها مربوطة بالسيرفر نفسه بس، مش مفتوحة عالشبكة.)

**حارس الدخول:** الاستوديو بيرفض أي طلب عنوانه (Host) مش `localhost` أو `127.0.0.1` (رد 400)، وبيرفض طلبات التعديل اللي مصدرها موقع تاني (رد 403). فنفق SSH بيمشي عادي، بس **لا تستعمل نفق إنترنت (ngrok وأمثاله) ولا تفتح المنفذ**. لو لازم اسم تاني (محوّل عكسي مثلاً) حطّه بـ `VP_ALLOWED_HOSTS` بملف `.env`.

## 7. فحص الصحة وربط الصندوق بالواجهة

```bash
docker compose -f docker-compose.engines.yml ps        # الحالة لازم تكون: healthy
curl http://127.0.0.1:8100/health                      # الصندوق العام
```

الجواب الصحيح بيشبه: `{"ok":true,"api":2,"backend":"diffusers","loaded":false,"loaded_model":null,"gpu":{"free_gb":…,"total_gb":…},…}`.
`"loaded": false` عادي: النموذج بينحمّل بأول شغلة (بتتأخر شوي)، وبيتفرّغ لحاله بعد 10 دقايق خمول.

**ربط الصندوق (من الواجهة، مرة وحدة):** «مصنع» ← «مكتبة النماذج» ← بطاقة «الصور» ← «＋ اربط نموذج» ← «أوزان على السيرفر» ← اختار قالب (مثل Qwen-Image) ← «التالي». بخطوة التفاصيل:

| الحقل | شو بتكتب | مثال |
|---|---|---|
| عنوان الصندوق | اسم الصندوق على الشبكة + المنفذ **الداخلي 8000** | `http://engine:8000` |
| توكن الصندوق | **اتركه فاضي على السيرفر** — النظام بياخد `ENGINE_TOKEN` من `.env` لحاله | (فاضي) |

اكبس «احفظ وافحص»: بتطلعلك حالة الصندوق (شغّال/واقف/توكن غلط) وذاكرة الكرت، وقائمة النماذج اللي لقاها بمجلد الأوزان مع حجم كل واحد ورخصته (من بطاقة النموذج: مساعدة بس، القرار إلك) أو سبب الرفض. اكبس «اختار» على نموذج، **«التالي»** ثم «احفظ» ثم «شغّل التجربة» — بتطلعلك صورة تجريبية. إذا عجبتك: «فعّله وخلّصنا ✓» (بيصير الافتراضي للصور، وإذا وقع بيرجع لمزوّد الصور الحالي لحاله).

- **للتكبير:** نفس الشي من بطاقة «التكبير» (الملف بيطلع باسم `upscale-RealESRGAN_x4plus`).
- **للتحريك (Wan أو LTX):** من بطاقة «التحريك» اكبس «＋ من صندوق الأوزان» وأضف النموذج لسجل موديلات التحريك. الأرقام (أقصى مدة، السرعة، ذاكرة الكرت) تقديرية — عدّلها من جدول موديلات التحريك بعد أول تجربة، وبالجدول زر «افحص الصندوق» بيتأكد إن النموذج موجود وسليم وبيدعم الوضع.
- **LTX:** رخصته مشروطة بحجم إيراد شركتك، فبيطلب تأكيدك قبل الإضافة.

(لو شغّلت النظام مباشرة على نفس الجهاز بدون Docker، عنوان الصندوق `http://127.0.0.1:8100`.)

**الصناديق القديمة (`--profile legacy`):** تنربط من جدول موديلات التحريك: «موديل جديد» ← نوع التشغيل «صندوق نموذج (http)» ← العنوان `http://ltx:8000` أو `http://wan:8000` (حقل «اسم النموذج بالصندوق العام» بيضل فاضي). بعد «احفظ» اكبس **«افحص الصندوق»**.

**ملاحظة:** على سيرفر لينكس مخزن الأسرار الخاص بويندوز مش موجود، فالنظام بياخد التوكن من متغير `ENGINE_TOKEN` (الـ compose بيمرّره من `.env` لحاله).

## 7.5 تجربة سريعة بلا كرت (على جهازك، قبل السيرفر)

عشان تشوف الواجهة والربط شغّالين بدون كرت ولا أوزان، شغّل «صندوق وهمي» على جهازك (بيرجّع صور ملوّنة وتكبير وفيديو تجريبي):

على ويندوز (PowerShell، من مجلد المشروع):

```powershell
$env:ENGINE_BACKEND="fake-images"; $env:ENGINE_PORT="8100"; $env:OUTPUT_DIR="$env:TEMP\vp_engine\out"; $env:LOCK_DIR="$env:TEMP\vp_engine\locks"; python -m services.engine.server
```

وعلى لينكس/ماك:

```bash
ENGINE_BACKEND=fake-images ENGINE_PORT=8100 OUTPUT_DIR=/tmp/vp_engine/out LOCK_DIR=/tmp/vp_engine/locks python -m services.engine.server
```

وبعدين بالواجهة اربط «أوزان على السيرفر» بالعنوان `http://127.0.0.1:8100` — بتلاقي أربع نماذج وهمية (`demo-image` و`demo-video` و`demo-audio` و`upscale-demo`) وبتجرّب كل الخطوات (احفظ ← جرّب ← فعّل) بدون أي تنزيل. هاد اختبار للسلسلة بس، مش جودة.

## 7.6 برامج النماذج (Gradio): موسيقى، مزامنة شفاه، وأي نموذج إله برنامج ويب

أغلب النماذج المفتوحة (ACE-Step للموسيقى، Wan2.2-S2V لمزامنة الشفاه…) بتجي مع **برنامج ويب Gradio**. النظام بيحكي معه بنفسه، وإنت بس بتربطه مرة وحدة:

1. شغّل برنامج النموذج على السيرفر (طريقة التشغيل بصفحته) وخلّيه يسمع على `127.0.0.1` بس (أو على اسم حاويته على شبكة `vidpattern_net`، مثل `http://acestep:7860`). **ما بيشتغل مع برنامج عليه كلمة سر.**
2. «مصنع» ← «مكتبة النماذج» ← البطاقة (مثلاً «الموسيقى») ← «＋ اربط نموذج» ← «برنامج نموذج (Gradio)» ← اختار قالب (مثل ACE-Step) ← «التالي».
3. حط رابط البرنامج (مثل `http://127.0.0.1:7860`) واكبس **«اقرا البرنامج»**: بيعرض نقاطه (الدوال اللي فيه) ومعاملات كل نقطة، وبيعلّم «مناسبة ✓» على اللي بتشبه مهمتك، وبيقترح ربط كل معامل بمدخلات الطلب (الوصف، المدة، الصورة، الصوت…). **راجع الاقتراح وعدّله**: لأي معامل بتختار «من الطلب» أو «قيمة ثابتة» أو «القيمة الجاهزة» (اللي حاطها صاحب البرنامج).
4. «التالي» ← «احفظ» ← «شغّل التجربة» ← «فعّله وخلّصنا ✓».

- **النظام بيتحقق قبل كل تشغيل** إن شكل النقطة ما اتغيّر: لو حدّثت البرنامج وتغيّرت معاملاته بيقلّك «أعد الربط» بدل ما يبعت مدخلات غلط بصمت.
- **الإلغاء:** لما بتلغي شغلة، النظام بيوقف الانتظار وبيطلب من البرنامج يلغي، بس **Gradio ما بيقدر يقتل دالة شغّالة** — ممكن البرنامج يكمّل بالخلفية لحد ما تخلص (والكرت يضل مشغول شوي).
- **الكرت:** النظام بيمسك قفل الكرت المشترك قبل ما يندهي البرنامج (لو النموذج معلّم «بيستعمل كرت الشاشة»)، فما بيشتغل مع صندوق الأوزان بنفس اللحظة.
- **انفحص فعلياً** بـ Gradio 4.44.1 و5.50.0 و6.30.0 الحقيقيين (فحص النقاط، توليد صور وصوت، رفع ملفات، تفريغ، إلغاء). **ما انفحص** مع برنامج ACE-Step أو Wan2.2-S2V نفسهم (بدّهم سيرفرك).

**الموسيقى والمؤثرات من المكتبة:** النموذج ممكن يكون برنامج Gradio (مثل ACE-Step) أو «أوزان على السيرفر» (Stable Audio، قسم 4). بعد ما تربط نموذج «الموسيقى» أو «المؤثرات» وتخلّيه الافتراضي: بـ«مكتبة الأصوات» لوحة «ولّد بنموذج من مكتبة النماذج»، وبكل طلب موسيقى/آهة معلّق زر «🎼 ولّد بنموذج المكتبة» (بدل الإضافة). **المقطع بيدخل المكتبة «غير معتمد»** وبينتظر سمعك — ما بيدخل أي فيديو بدون اعتمادك. الموسيقى بتنطلب دايماً «بلا غناء ولا كلام»، وما في رجوع تلقائي لطريقة تانية لو وقع النموذج (الصوت ما بيتبدّل بصمت).

**مزامنة الشفاه من المكتبة:** لو ربطت نموذج «مزامنة الشفاه» وخلّيته الافتراضي، كل موديل تحريك ما إله أمر مزامنة بسجله بيصير مناسب للقطات الكلام على الكاميرا (النظام بيحرّك اللقطة بالموديل، وبعدين بيمرّر الفيديو والصوت لنموذج المزامنة). أمر المزامنة الخاص بالموديل بيضل الأولى. لو وقعت المزامنة بتطلعلك الرسالة (ما في بديل تلقائي).

## 8. التحديث

```bash
# انسخ ملفات المشروع الجديدة فوق القديمة (نفس المجلد)
docker compose -f docker-compose.engines.yml up -d --build    # بيعيد بناء الصندوق ويشغّله
docker compose up -d --build
docker image prune -f                                         # ينظّف الصور القديمة
```

الأوزان وبيانات `library/` ما بتتأثر. (تحديث الصندوق بعد نسخة جديدة من هالمشروع مرة وحدة: لازم `docker volume create vidpattern_gpu_locks` تكون عملتها قبل.)

## 9. الإيقاف والسجلات

```bash
docker compose -f docker-compose.engines.yml stop          # إيقاف الصندوق (بيضل موجود)
docker compose -f docker-compose.engines.yml down          # إيقاف وحذف الحاوية (الأوزان والمكتبة سليمة)
docker compose -f docker-compose.engines.yml logs -f engine # شوف شو عم يصير بالصندوق العام
docker compose stop                                        # إيقاف النظام نفسه
```

الصندوق بيشتغل لحاله بعد إعادة تشغيل السيرفر (`restart: unless-stopped`).

## 10. إذا طلعت رسالة «الذاكرة ما كفّت»

يعني كرت الشاشة خلّص ذاكرته وقت التوليد. **ما في داعي تخاف:** الصندوق بيضل شغّال وبيفرّغ النموذج لحاله، والنظام بيجرّب الطريقة الحالية (للصور) أو موديل تحريك ثاني تلقائياً.

جرّب بالترتيب:

1. **قصّر اللقطة أو قلّل الدقة.** مثال: حط `MAX_PIXELS=399360` بملف `.env` (يعني حوالي 480×832) وأعد التشغيل.
2. **خلّي الصندوق يوفّر ذاكرة:** حط `ENGINE_OFFLOAD=model` بـ `.env` (أبطأ شوي بس بياخد ذاكرة أقل بكتير).
3. **شوف مين ماسك الكرت:** `nvidia-smi`. إذا في برنامج ثاني (غير الصندوق) واخد ذاكرة، سكّره.
4. **أعد تشغيل الصندوق:** `docker compose -f docker-compose.engines.yml restart engine` (بيفضّي أي ذاكرة معلّقة).
5. **قلّل الخطوات:** بإعدادات النموذج بالواجهة، حقل «الخطوات» (مثال: 20 بدل 30) — جودة أقل بشوي وذاكرة ووقت أقل.
6. جرّب نموذج أخف (FLUX.1-schnell للصور، LTX للتحريك).

## 11. ملاحظات أمان

- **المنافذ:** `127.0.0.1` فقط. ما تغيّرها لـ `0.0.0.0` ولا تفتحها بالـ firewall.
- **الأوزان:** مركّبة `:ro` (قراءة فقط)، والصندوق نفسه `read_only` ومستخدمه مش root. تحميلها `safetensors` بس وبلا كود خارجي (`trust_remote_code` ممنوع) ومن المجلد المحلي بس.
- **مجلد أقفال الكرت:** حجم صغير مشترك بين الصندوق والنظام (ملفات قفل ونصوص تسليم بس). مفتوح للكتابة لمستخدمين مختلفين (الصندوق 10001 والنظام `APP_UID`) لأنو ما فيه غير هالملفات الصغيرة.
- **الإنترنت:** الصندوق مضبوط «أوفلاين» (ما بينزّل نماذج ولا بيبعت إحصاءات). لكن Docker بيعطيه شبكة عادية عشان المنفذ يشتغل؛ لو بدك تقطع خروجه للإنترنت تماماً: على السيرفر ضيف قاعدة بـ `DOCKER-USER` (iptables) بتمنع الخروج من شبكة `vidpattern_net` لغير الشبكات الداخلية. اسألني وبكتبلك الأمر الدقيق حسب سيرفرك.
- **التوكن:** لو شكّيت إنه انكشف: ولّد واحد جديد (`openssl rand -hex 32`)، بدّله بـ `.env`، أعد التشغيل (وإذا حفظته بالواجهة حدّثه من بطاقة الصندوق).

## 11.5 حسابات الموظفين (الدخول)

الاستوديو بيطلب دخول لكل `/api/*`. **أول مرة** (ما في أي حساب) الصفحة بتفتح شاشة «أنشئ أول حساب» — بس من نفس الجهاز اللي شغّال عليه الاستوديو.
على Docker المتصفح بيجي من «برّا» الحاوية، فالأسلم تنشئ الحساب الأول من السيرفر:

```bash
docker compose exec app python accounts.py create اسم_المستخدم "الاسم الظاهر"
```

(بيسألك كلمة السر مخفية.) أو حط `VP_ALLOW_REMOTE_SETUP=1` بملف `.env` مؤقتاً وافتح الصفحة، ثم شيله وأعد التشغيل.

- كل موظف بيضيفه صاحب الحساب من الإعدادات ← «الموظفين» بكلمة سر مؤقتة بيغيّرها بأول دخول. ما في صلاحيات: كلهم متساويين، والنظام بيسجّل مين عمل شو (الإعدادات ← «النشاط»).
- **نسيت كلمة السر:** `docker compose exec app python accounts.py reset اسم_المستخدم`.
- الدخول مربوط بالعنوان: `localhost` غير `127.0.0.1` غير عنوان الشبكة — استعمل عنوان واحد.
- على الشبكة المحلية الاتصال HTTP بلا تشفير: شبكة مكتب موثوقة بس.
- رخصة Remotion (المونتاج المتقدّم) مجانية لحد 3 أشخاص؛ من الرابع بيلزم رخصة شركة (النظام بيذكّرك لما تضيف الرابع).
- بعد الترقية: أعد بناء الصورة (`docker compose build`) لأنو مكتبة `argon2-cffi` انضافت.
