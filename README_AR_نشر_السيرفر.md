# نشر النظام وصناديق النماذج على السيرفر — خطوة بخطوة

> **تنبيه مهم:** صناديق LTX وWan **انكتبت ما انجرّبت على كرت شاشة حقيقي**. الاختبارات اللي ركضت كانت بنموذج «وهمي» بيثبت إن السلسلة كلها شغّالة (الطابور، القفل، الإلغاء، الرسائل، الربط بالتحريك). أول تشغيل حقيقي على السيرفر لازم يكون وإنت قاعد، وإذا طلع خطأ غريب ابعتلي نص الخطأ من `docker compose logs`.

## شو هو «الصندوق»؟

كل نموذج تحريك (LTX، Wan) بيشتغل بحاوية Docker لحاله، متل «غرفة مقفولة» فيها كل مكتباته. النظام (VidPattern) بيحكي معها بعنوان داخلي.
**مثال:** لما بتطلب تحريك لقطة، النظام بيبعت الصورة والوصف لصندوق LTX، بيستنى، وبيستلم الفيديو الجاهز. إذا LTX وقع، النظام لحاله بيجرّب Wan (البديل التلقائي).

**قفل الكرت:** الكرت بيشتغل عليه صندوق واحد بكل لحظة. لو Wan شغّال وانطلب LTX، LTX بيستنى دوره وما بينهار. ولما LTX بيدخل، Wan بيفرّغ نفسه من ذاكرة الكرت أول.

---

## 1. اللي بدك إياه

- سيرفر لينكس (Ubuntu 22.04 أو أحدث) فيه كرت NVIDIA، وتعريف الكرت (driver) مركّب.
- تتأكد إن الكرت شغّال: اكتب `nvidia-smi` — لازم يطلعلك جدول فيه اسم الكرت وذاكرته.
- مساحة فاضية: حوالي 60 GB للأوزان + 20 GB للصور.

## 2. تركيب Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER        # بعدها اطلع وادخل من جديد عشان تشتغل بدون sudo
docker --version                     # لازم يطلع رقم نسخة
```

## 3. تركيب nvidia-container-toolkit (عشان Docker يشوف الكرت)

هالأوامر من توثيق NVIDIA الرسمي — لو الروابط تغيّرت شوف توثيقهم (search: NVIDIA Container Toolkit install).

```bash
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

**اختبار:** لازم يطلعلك نفس جدول `nvidia-smi` من جوّا حاوية:

```bash
docker run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu22.04 nvidia-smi
```

## 4. وضع الأوزان (النماذج)

الأوزان ملفات ضخمة بتنزّلها **مرة وحدة** وبتحطها بمجلد واحد. الصناديق بتقراها «للقراءة فقط» وما بتنزّل شي من الإنترنت وقت التشغيل.

| النموذج | المصدر على Hugging Face | الحجم | الترخيص | المجلد المطلوب |
|---|---|---|---|---|
| Wan2.2 TI2V 5B (تحريك الناس والحركة المعقدة) | `Wan-AI/Wan2.2-TI2V-5B` — **بصيغة diffusers**: بتنزّل نسخة `Wan-AI/Wan2.2-TI2V-5B-Diffusers` (نفس النموذج، بس مرتّب بالشكل اللي الصندوق بيقراه) | حوالي 34 GB | Apache-2.0 (استخدام تجاري مسموح) | `models/engines/Wan2.2-TI2V-5B-Diffusers` |
| LTX-Video نسخة 2B (تحريك سريع للحركة البسيطة) | `Lightricks/LTX-Video` (نسخة 2B فقط) | حوالي 6.3 GB | **«other»** — ترخيص خاص بالأوزان، **راجعه بنفسك قبل أي استخدام تجاري** | `models/engines/LTX-Video` |
| LatentSync 1.6 (مزامنة الشفاه) | `ByteDance/LatentSync-1.6` | حوالي 9.6 GB | راجع صفحة النموذج | `models/engines/LatentSync-1.6` — **للمستقبل، لسا ما إله صندوق** |

**طريقة التنزيل** (من جهاز أو سيرفر عليه إنترنت، وبعدين انسخ المجلد للسيرفر لو لزم):

```bash
pip install -U "huggingface_hub[cli]"
huggingface-cli download Wan-AI/Wan2.2-TI2V-5B-Diffusers --local-dir ./models/engines/Wan2.2-TI2V-5B-Diffusers
huggingface-cli download Lightricks/LTX-Video            --local-dir ./models/engines/LTX-Video
```

**كيف تتأكد إن المجلد صح:** جوّا كل مجلد لازم تلاقي ملف اسمه `model_index.json` ومجلدات متل `transformer` و`vae`. إذا ما لقيته يعني نزّلت صيغة غلط. إذا ريبو LTX فيه نسخ كبيرة (13B) مش محتاجها، استثنيها بـ `--exclude` وراجع صفحة النموذج.

> هالجداول والأحجام جاية من خطة المونتاج، وما قدرت أتأكد منها من الإنترنت لأني ما نزّلت شي.

## 5. الإعدادات (ملف .env)

```bash
cp .env.example .env
openssl rand -hex 32          # بيطلّع كلمة عشوائية طويلة، انسخها
nano .env                     # حطها بعد ENGINE_TOKEN= واحفظ
chmod 600 .env                # بس إنت بتقرا الملف
```

**التوكن** هو «كلمة السر» بين النظام والصناديق. بدونها أي حدا على السيرفر ما بيقدر يطلب منها شي. **لا ترسله لأي حدا ولا تكتبه بمحادثة.**

## 6. التشغيل

```bash
docker network create vidpattern_net                          # مرة وحدة بس: الشبكة اللي بتجمع النظام والصناديق
docker compose -f docker-compose.engines.yml up -d --build    # أول مرة بتاخد وقت (بيبني الصور)
docker compose up -d --build                                  # النظام نفسه
```

**الواجهة:** `http://127.0.0.1:8000` على السيرفر. للدخول من جهازك استعمل نفق SSH: `ssh -L 8000:127.0.0.1:8000 user@server` وافتح `http://127.0.0.1:8000` عندك. (المنافذ كلها مربوطة بالسيرفر نفسه بس، مش مفتوحة عالشبكة.)

**حارس الدخول:** الاستوديو بيرفض أي طلب عنوانه (Host) مش `localhost` أو `127.0.0.1` (رد 400)، وبيرفض طلبات التعديل اللي مصدرها موقع تاني (رد 403). فنفق SSH بيمشي عادي، بس **لا تستعمل نفق إنترنت (ngrok وأمثاله) ولا تفتح المنفذ**. لو لازم اسم تاني (محوّل عكسي مثلاً) حطّه بـ `VP_ALLOWED_HOSTS` بملف `.env`.

## 7. فحص الصحة

```bash
docker compose -f docker-compose.engines.yml ps        # الحالة لازم تكون: healthy
curl http://127.0.0.1:8101/health                      # LTX
curl http://127.0.0.1:8102/health                      # Wan
```

الجواب الصحيح بيشبه: `{"ok":true,"backend":"ltx","loaded":false,"queued":0,"running":0,...}`.
`"loaded": false` عادي: النموذج بينحمّل بأول لقطة (بتتأخر شوي)، وبيتفرّغ لحاله بعد 10 دقايق خمول.

**من الواجهة:** مصنع ← النماذج المحلية ← «موديل جديد»، واختار «نوع التشغيل: صندوق نموذج (http)»:

| الحقل | شو بتكتب | مثال |
|---|---|---|
| عنوان الصندوق | اسم الصندوق على الشبكة + المنفذ **الداخلي 8000** | LTX: `http://ltx:8000` — Wan: `http://wan:8000` |
| الوضع | صورة لفيديو | i2v |
| اسم مفتاح التوكن | أي اسم بالإنجليزي | `engine_ltx` |
| التوكن | نفس قيمة `ENGINE_TOKEN` من ملف `.env` | (الصقها هون) |

بعد «احفظ» اضغط **«افحص الصندوق»**: بيقلك بالعربي إذا شغّال وجاهز، أو واقف، أو الكرت مشغول.
(لو شغّلت النظام مباشرة على نفس الجهاز بدون Docker، العنوان `http://127.0.0.1:8101` لـ LTX و`http://127.0.0.1:8102` لـ Wan.)

**ملاحظة:** على سيرفر لينكس مخزن الأسرار الخاص بويندوز مش موجود، فالنظام بياخد التوكن من متغير `ENGINE_TOKEN` (الـ compose بيمرّره من `.env` لحاله).

## 8. التحديث

```bash
# انسخ ملفات المشروع الجديدة فوق القديمة (نفس المجلد)
docker compose -f docker-compose.engines.yml up -d --build    # بيعيد بناء الصناديق ويشغّلها
docker compose up -d --build
docker image prune -f                                         # ينظّف الصور القديمة
```

الأوزان وبيانات `library/` ما بتتأثر.

## 9. الإيقاف والسجلات

```bash
docker compose -f docker-compose.engines.yml stop        # إيقاف الصناديق (بتضل موجودة)
docker compose -f docker-compose.engines.yml down        # إيقاف وحذف الحاويات (الأوزان والمكتبة سليمة)
docker compose -f docker-compose.engines.yml logs -f ltx # شوف شو عم يصير بصندوق LTX
docker compose stop                                      # إيقاف النظام نفسه
```

الصناديق بتشتغل لحالها بعد إعادة تشغيل السيرفر (`restart: unless-stopped`).

## 10. إذا طلعت رسالة «الذاكرة ما كفّت»

يعني كرت الشاشة خلّص ذاكرته وقت التوليد. **ما في داعي تخاف:** الصندوق بيضل شغّال وبيفرّغ النموذج لحاله، والنظام بيجرّب موديل ثاني تلقائياً (بتشوف الاتنين بقائمة «آخر المحاولات»).

جرّب بالترتيب:

1. **قصّر اللقطة أو قلّل الدقة.** مثال: حط `MAX_PIXELS=399360` بملف `.env` (يعني حوالي 480×832) وأعد التشغيل.
2. **خلّي الصندوق يوفّر ذاكرة:** حط `ENGINE_OFFLOAD=model` بـ `.env` (أبطأ شوي بس بياخد ذاكرة أقل بكتير).
3. **شوف مين ماسك الكرت:** `nvidia-smi`. إذا في برنامج ثاني (غير الصناديق) واخد ذاكرة، سكّره.
4. **أعد تشغيل الصندوق:** `docker compose -f docker-compose.engines.yml restart wan` (بيفضّي أي ذاكرة معلّقة).
5. **قلّل الخطوات:** بإعدادات الموديل بالواجهة، حقل «عدد الخطوات» (مثال: 20 بدل 30) — جودة أقل بشوي وذاكرة ووقت أقل.
6. إذا ضلّ يتكرر مع Wan: خلّي LTX هو الأساسي (نسخة 2B أخف بكتير)، واترك Wan للقطات اللي بتحتاج وجوه.

## 11. ملاحظات أمان

- **المنافذ:** `127.0.0.1` فقط. ما تغيّرها لـ `0.0.0.0` ولا تفتحها بالـ firewall.
- **الأوزان:** مركّبة `:ro` (قراءة فقط)، والصندوق نفسه `read_only` ومستخدمه مش root.
- **الإنترنت:** الصناديق مضبوطة «أوفلاين» (ما بتنزّل نماذج ولا بتبعت إحصاءات). لكن Docker بيعطيها شبكة عادية عشان المنفذ يشتغل؛ لو بدك تقطع خروجها للإنترنت تماماً: على السيرفر ضيف قاعدة بـ `DOCKER-USER` (iptables) بتمنع الخروج من شبكة `vidpattern_net` لغير الشبكات الداخلية. اسألني وبكتبلك الأمر الدقيق حسب سيرفرك.
- **التوكن:** لو شكّيت إنه انكشف: ولّد واحد جديد (`openssl rand -hex 32`)، بدّله بـ `.env`، أعد التشغيل، وحدّثه بإعدادات الموديل بالواجهة.

## 11.5 حسابات الموظفين (الدخول)

الاستوديو بيطلب دخول لكل `/api/*`. **أول مرة** (ما في أي حساب) الصفحة بتفتح شاشة «أنشئ أول حساب» — بس من نفس الجهاز اللي شغّال عليه الاستوديو.
على Docker المتصفح بيجي من «برّا» الحاوية، فالأسلم تنشئ الحساب الأول من السيرفر:

```bash
docker compose exec app python accounts.py create اسم_المستخدم "الاسم الظاهر"
```

(بيسألك كلمة السر مخفية.) أو حط `VP_ALLOW_REMOTE_SETUP=1` بملف `.env` مؤقتاً وافتح الصفحة، ثم شيله وأعد التشغيل.

- كل موظف بيضيفه صاحب الحساب من الإعدادات ← «الموظفين» بكلمة سر مؤقتة بيغيّرها بأول دخول. ما في صلاحيات: كلهم متساويين، والنظام بيسجّل مين عمل شو (الإعدادات ← «النشاط»).
- **نسيت كلمة السر:** `docker compose exec app python accounts.py reset اسم_المستخدم`.
- الدخول مربوط بالعنوان: `localhost` غير `127.0.0.1` غير عنوان الشبكة — استعمل عنوان واحد.
- على الشبكة المحلية الاتصال HTTP بلا تشفير: شبكة مكتب موثوقة بس.
- رخصة Remotion (المونتاج المتقدّم) مجانية لحد 3 أشخاص؛ من الرابع بيلزم رخصة شركة (النظام بيذكّرك لما تضيف الرابع).
- بعد الترقية: أعد بناء الصورة (`docker compose build`) لأنو مكتبة `argon2-cffi` انضافت.

## 12. شو انفحص وشو لا

| انفحص فعلياً (بدون كرت) | ما انفحص أبداً (بدّه سيرفرك) |
|---|---|
| الطابور، قفل الكرت بين صندوقين، الإلغاء، رسالة «الذاكرة ما كفّت»، التوكن، حدود الصور، تنظيف الملفات، الربط بالتحريك والبديل التلقائي | تشغيل LTX وWan فعلياً على كرت، بناء صور Docker، ثبات إصدارات المكتبات بـ `requirements-*.txt`، سرعة التوليد وجودته، تفريغ الذاكرة الفعلي |
